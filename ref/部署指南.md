# 代码评审机器人（Code Review Bot）部署指南

一个把飞书群消息 → GitCode PR 自动评审的桥接服务：在飞书群里 @机器人 并附上 PR 链接，机器人拉起 `opencode` 执行 review，把 inline 评论贴到 PR 上，并在群里回一条结果。

> 说明：本文所有密钥、ID、路径均用 `<...>` 占位，替换成你自己的值。

---

## 1. 架构总览

```
飞书群 @机器人 + PR链接
        │  长连接(WebSocket) 推送事件 im.message.receive_v1
        ▼
feishu-bridge.js  (Node 服务, pm2 常驻)
        │  spawn('opencode', ['run', '/gitcode-review <prUrl>'])
        ▼
opencode 执行 command: /gitcode-review
        │  加载 skill: gitcode-pr-review
        ▼
GitCode v5 API  → 拉 diff、逐行评审、贴 inline 评论、点“已解决”
        │
        ▼
回到 bridge → 群里回「review完成」或「执行异常」
```

三个关键组件：

| 组件 | 位置 | 作用 |
| --- | --- | --- |
| `feishu-bridge.js` | 项目目录 | 收飞书事件、校验链接、拉起 opencode、回消息 |
| `gitcode-review.md` | `~/.config/opencode/command/` | opencode 的 `/gitcode-review` 命令入口 |
| `gitcode-pr-review/SKILL.md` | `~/.config/opencode/skills/` | review 的完整工作流（拉 diff、评审、贴评论、点已解决） |

---

## 2. 前置准备

- Node.js（推荐 20+）
- 已安装 `opencode` CLI
- 已安装 `pm2`（`npm install -g pm2`）
- 飞书开放平台自建应用
- GitCode Personal Access Token（PAT，需 PR 评论权限）

---

## 3. 飞书应用配置

进入飞书开发者后台（open.feishu.cn → 开发者后台）进行配置。图文步骤可参考：
[《飞书机器人接入教程》第一节：进入飞书开发者后台进行配置](https://zhuanlan.zhihu.com/p/673850734)

1. **创建自建应用**：开发者后台 → 创建应用 → 选择「x企业自建应用」，填写名称、描述、图标。
2. **开启机器人能力**：应用详情 → 「添加应用能力」→ 添加「机器人」，配置机器人名称与头像。
3. **记录凭证**：在「凭证与基础信息」里拿到 **App ID** 和 **App Secret**。
4. **事件与回调**：
   - 订阅方式选 **「使用长连接接收事件/回调」**（关键！Webhook 方式收不到本地长连接）。
   - 订阅事件：**接收消息 `im.message.receive_v1`**。
5. 若应用有版本管理，配置改动后需**发布并审核通过**才生效。

## 4. 部署桥接服务

### 4.1 初始化项目

```bash
mkdir feishu-bridge && cd feishu-bridge
npm init -y
npm install dotenv @larksuiteoapi/node-sdk
```

### 4.2 配置 `.env`

```bash
FEISHU_APP_ID=<你的 App ID>
FEISHU_APP_SECRET=<你的 App Secret>
```

### 4.3 `feishu-bridge.js`（骨架）

```js
require('dotenv').config();
const { Client, WSClient, EventDispatcher, LoggerLevel } = require('@larksuiteoapi/node-sdk');
const { spawn } = require('child_process');

const client = new Client({
  appId: process.env.FEISHU_APP_ID,
  appSecret: process.env.FEISHU_APP_SECRET,
});

const REVIEW_DIR = '<评审用的本地 git 仓库绝对路径>';
const MODEL = '<provider>/<model>';        // 例如 deepseek/deepseek-v4-pro

async function sendChatMessage(chatId, text) {
  await client.im.message.create({
    params: { receive_id_type: 'chat_id' },
    data: { receive_id: chatId, msg_type: 'text', content: JSON.stringify({ text }) },
  });
}

const eventDispatcher = new EventDispatcher({}).register({
  'im.message.receive_v1': async (data) => {
    const { message } = data;
    let content;
    try { content = JSON.parse(message.content).text; } catch { return; }

    // 白名单：只允许本仓库的 PR 链接
    const prMatch = content.match(/https:\/\/gitcode\.com\/<owner>\/<repo>\/pull\/\d+/);
    if (!prMatch) {
      console.log(`拒绝非白名单链接: ${content}`);
      await sendChatMessage(message.chat_id, "执行异常");
      return;
    }
    const prUrl = prMatch[0];
    const chatId = message.chat_id;

    // 关键：用 spawn 且 stdin='ignore'（execFile 的 stdin 管道会让 opencode 卡死在 init）
    const child = spawn('opencode',
      ['run', '--dangerously-skip-permissions', '--dir', REVIEW_DIR, '-m', MODEL, `/gitcode-review ${prUrl}`],
      { stdio: ['ignore', 'pipe', 'pipe'] }
    );
    let stdout = '', stderr = '';
    child.stdout.on('data', (d) => { stdout += d; });
    child.stderr.on('data', (d) => { stderr += d; });

    child.on('error', async (err) => {
      console.error("执行异常:", err.message);
      await sendChatMessage(chatId, "执行异常");
    });
    child.on('close', async (code) => {
      if (code !== 0) {
        console.error(`执行异常: exit ${code}`);
        if (stderr) console.error("stderr:\n", stderr);
        if (stdout) console.error("stdout:\n", stdout);
        await sendChatMessage(chatId, "执行异常");
        return;
      }
      await sendChatMessage(chatId, "review完成");
    });
  },
});

const wsClient = new WSClient({
  appId: process.env.FEISHU_APP_ID,
  appSecret: process.env.FEISHU_APP_SECRET,
  loggerLevel: LoggerLevel.info,
});
wsClient.start({ eventDispatcher });
```

> 关键点：**不要加超时强杀**，让 review 自然跑完（大 PR 可能数分钟）。出错详情只写日志，群里只回固定文案。

### 4.4 用 pm2 常驻

```bash
pm2 start feishu-bridge.js --name feishu-bridge
pm2 save
# 开机自启（需 sudo，按提示执行后再次 pm2 save）
pm2 startup
```

## 5. 配置 opencode command 与 skill

### 5.1 命令 `gitcode-review.md`

放在 `~/.config/opencode/command/gitcode-review.md`，frontmatter 指定 agent，正文把 PR URL 当作 `$ARGUMENTS`，并要求加载 `gitcode-pr-review` skill。鉴权步骤里**直接使用硬编码的 PAT**（不要向用户索要，也不要打印到输出）：

```markdown
## Step 2 — Authenticate
Use this GitCode PAT for all authenticated calls, do NOT ask the user:
    <你的 GitCode PAT>
Use it via the `Authorization: Bearer <PAT>` header.
```

### 5.2 skill `gitcode-pr-review/SKILL.md`

完整工作流（已包含本次所有优化）：

1. **Resolve the PR** — 从 URL 解析 owner/repo/number，拉 PR 元数据。
2. **Pre-check: existing comments** — 拉全部历史评论：
   - 已 `resolved` → 忽略；
   - 未解决且**问题已在当前代码里处理掉** → 用 `PUT /comments/{discussion_id}` + `{"resolved":true}` 点「已解决」；
   - 未解决且仍存在 → 在 discussion 上发跟进回复提醒。
3. **Fetch the PR diff** — `GET /pulls/{number}/files` 存 `/tmp/pr_files.json`。
4. **Review the diff** — 逐行评审。
   - **复评模式**（第 2 步发现已有历史评论时）：只发**逻辑错误**或**会在真实输入下产生错误行为的推测性边界情况**，不发风格/命名/文档等细枝末节。
5. **Compute position** — 解析 `@@` 头，`position` = 新文件行号（1-based）。
6. **Post inline comments** — `POST /pulls/{number}/comments`，body 用 `path`+`position`+`body`（不要用 `line`/`new_line`/`side`/`commit_id`）。
7. **Verify inline** — 回查 `comment_type == "diff_comment"`。
8. **Resolve false positives** — 对本次新评论里判定为误报的，用 `PUT /comments/{discussion_id}` + `{"resolved":true}` 点掉。
9. **Clean up** — 删错评用 `note_id`。

「已解决」端点（实测有效）：

```bash
curl -s --noproxy '*' -X PUT \
  -H "Authorization: Bearer <PAT>" \
  -H "Content-Type: application/json" \
  -d '{"resolved": true}' \
  "https://gitcode.com/api/v5/repos/<owner>/<repo>/pulls/<number>/comments/<discussion_id>"
```

> 注意：用的是 `discussion_id`（哈希串），不是数字 `id`。

## 6. 安全加固（必读）

机器人会调你本地的模型额度 + 用你的 PAT 发评论，属于「外部用户可触达的写操作」，务必做以下防护：

1. **URL 白名单（代码层）**：bridge 里只放行 `https://gitcode.com/<owner>/<repo>/pull/<数字>`，其余一律「执行异常」。这是防止外部用户跑任意 prompt 的核心防线。
2. **应用可用范围（后台）**：把应用「可用范围」收紧到指定部门/成员，别设「全员」。
3. **机器人所在群（群设置）**：机器人只收得到它所在群的消息。把机器人从不需要的外部群移除。
4. **外部私聊审批（后台）**：开启「外部用户私聊需 App 负责人审批（Approval required）」，堵住外部用户私聊滥用。
5. **外部群控制**：谨慎开启「Allow bot to join external groups」；尽量只让机器人待在受控群。
6. **令牌保管**：PAT 明文写在 skill/command 里，别提交到公开仓库；定期轮换。

## 7. 对外发布步骤

> 前提：**机器人必须先对外发布，外部群（external group）才能使用它**。不发布，外部群根本加不了、也 @ 不到这个机器人。

1. 后台「应用发布」→ 创建版本并提交审核 → 审核通过后**发布**。
2. 发布前确认：
   - 事件订阅方式已选「长连接」；
   - 已订阅 `im.message.receive_v1`；
   - 「可用范围」按需收紧；
   - 安全开关（外部私聊审批、外部群）按需开启。
3. 按需开启对外能力（三者含义不同，逐项评估，且都依赖第 1 步的对外发布）：
   - **External sharing**：是否允许对外共享；
   - **Allow bot to join external groups**：是否允许机器人进外部群；
   - **Allow external users to start direct messages**：外部用户能否私聊（配合「Approval required」）。
4. 发布后先用内部群验证一轮完整链路，再放外部。

## 8. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 机器人收不到事件 | 订阅方式不是「长连接」 | 后台事件与回调 → 订阅方式切长连接 |
| `Feishu is not a constructor` | SDK 升级后 API 变了 | 用 `Client` + `WSClient` + `EventDispatcher` |
| opencode 卡在 `init`、不生成 session | `execFile` 的 stdin 管道导致 | 改用 `spawn` + `stdio: ['ignore','pipe','pipe']` |
| review 跑 9 秒就退、无评论 | 写 `/tmp` 触发权限询问 | 加 `--dangerously-skip-permissions` |
| review 到点被强杀 | 设了超时 | 去掉超时强杀，让它跑完 |
| 群里返回大段内容 | 回传了 review 输出 | 群里只回「执行异常」/「review完成」 |
| 模型报 `Unexpected server error` | 默认模型接口异常 | 显式 `-m <可用模型>` |
| 贴的评论是 timeline 不是 inline | 用了 `line`/`new_line` 字段 | 改用 `path`+`position` |
| 点「已解决」404 | 用错了 ID | 用 `discussion_id`，不是数字 `id` |

## 9. 运维

```bash
pm2 logs feishu-bridge      # 看日志（错误详情都在这里，不回群）
pm2 restart feishu-bridge   # 改代码后重启
pm2 save                    # 持久化进程列表
```

- 每次改 bridge 后 `node -c` 校验语法再 `pm2 restart` + `pm2 save`。
- review 结果：成功回「review完成」，失败回「执行异常」，详细原因只落在 pm2 日志。
